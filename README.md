# Media Photo Workbench / 融媒体图片工作台

## 项目简介

Media Photo Workbench / 融媒体图片工作台 是面向校园融媒体中心、新闻中心和影像部门的 Windows 桌面端图片工作台。

它用于活动现场图片导入、筛选、修图流转、客户端协作、导出发布和归档管理。系统以一台主机为中心，集中保存图片仓库和 SQLite 数据库，多台客户端设备可在同一局域网内上传图片、查看图片墙、打星、分类、修改状态、下载待修包并回传已修图。

本项目不是云盘，也不是实时传图系统。当前重点是本地主机集中存储和局域网协作。

## 使用方式

1. 下载发布页提供的 Windows ZIP 便携包。
2. 将 ZIP 解压到非系统盘目录，例如 `D:\MediaPhotoWorkbench`。
3. 双击运行 `Media Photo Workbench.exe` 或 `融媒体图片工作台.exe`。
4. 不要直接在压缩包内运行程序。
5. 首次使用建议先进入系统设置，选择图片仓库路径。

## 主机端快速开始

1. 启动软件，选择“启动为主机”。
2. 进入“系统设置”，设置图片仓库路径。
3. 进入“活动管理”，创建并激活活动。
4. 进入“导入图片”，导入 JPG / JPEG / PNG 图片。
5. 在主机首页查看本机地址、局域网地址和二维码。
6. 等待客户端通过地址或二维码连接。

主机端负责活动、仓库、数据库、图片处理、任务中心、导出发布和归档。

## 客户端快速开始

1. 确认客户端设备与主机在同一局域网，或连接到主机开启的 Windows 热点。
2. 通过主机首页显示的地址或二维码打开客户端页面。
3. 设置设备名，例如“修图电脑A”或“摄影组1号”。
4. 选择活动并上传 JPG / JPEG / PNG 图片。
5. 在客户端图片墙进行查看、打星、分类和状态修改。
6. 在客户端修图任务页下载待修包并回传已修图。

客户端设备名会保存在本机浏览器 / 客户端 localStorage 中，用于主机识别上传来源和操作记录。

## 推荐网络方式

- 同一 Wi-Fi 或有线局域网可用时，直接使用主机首页显示的局域网地址。
- 校园网可能存在设备隔离，即使连接同一个 Wi-Fi 也可能无法互访。
- 如果校园网无法连接，推荐主机开启 Windows 热点，其他设备连接该热点。
- Windows 热点常见主机地址候选为 `192.168.137.1`，实际地址和端口以主机首页 / 相机 FTP 页面检测结果为准。
- 必要时检查 Windows 防火墙是否允许本软件访问专用网络。

## 相机 FTP 传输（v1.1.0-alpha.4）

v1.1.0-alpha 使用 Windows IIS FTP 单一架构。工作台负责检测、初始化、修复、启停和显式接管 IIS FTP 站点；普通启动不要求管理员权限，只有修改 Windows 功能、IIS、本地账户、ACL 或防火墙时才会显示 UAC。

当前自动配置统一采用 `Preflight（只读）→ Plan → Apply（一次 UAC）→ Verify → Commit / Rollback`。setup、repair、start、restart 和 adopt-site 只改变目标意图，底层都由同一 IIS reconciliation 事务完成；start 发现配置缺失时会先修复再启动。Plan 会把项目分成“已符合 / 将创建 / 将更新 / 将修复 / 需要确认 / 阻塞”，只有无关 IIS 站点、外部程序、非工作台账户等不能安全处理的资源才阻止执行。高风险 ACL 收紧、服务器级 PASV 和显式接管会在计划确认弹窗中逐项说明。

接收目录 ACL 修改前会保存 DACL SDDL。若目录因旧配置或继承转换形成非规范顺序，工作台会先保留原规则并按 Deny/Allow 规范顺序重建，再添加相机账户权限；写入后验证实际读写能力。失败回滚会重新应用原 SDDL 并精确验证，不能完整恢复时不会误报成功，也不会删除本轮账户而留下新的孤立 SID。

相机 FTP 页在服务运行时优先显示“相机 FTP 已启动”、当前活动、连接参数、近期相机活动和最近接收文件；账户、端口、IIS 深度检测与高级管理按需展开。最近文件按同一落盘路径只展示最新有效状态，用绿色表示导入成功、蓝色表示接收或处理中、黄色/灰色表示跳过，只有真实失败使用红色；零值统计和重复说明默认隐藏。应用内管理确认框在较小窗口和 Windows 缩放下固定标题与底部操作，中间内容独立滚动；Windows 系统 UAC 窗口不受应用控制。

已配置 FTP 账户会显示“密码已设置”，刷新页面不会再用空密码框造成“是否设置成功”的歧义；真实密码仍不会被读取、回显或保存。watcher 会持久化已成功处理文件的非敏感指纹，并从旧版本已有相机 FTP 图片记录引导首次回执；工作台重启时不重复导入未变化的历史文件，停机期间新增或内容发生变化的文件仍会正常处理。

- 当前仅支持 Windows 11 和局域网普通 FTP；不支持 FTPS、SFTP、公网远传、RAW 或视频。
- 控制端口默认并推荐使用 `21`，可在 `1-65535` 范围内修改；PASV 默认 `50000-50100`，binding 始终为 `*:{当前控制端口}:`，不把热点 IP 写死到 IIS。控制端口不能落入被动端口范围。
- 普通权限只能确认 TCP 是否正在监听；若 IIS 配置不可读且端口未监听，页面显示“需管理员确认”，不会误报“可用”。用户点击端口检测后按需请求 UAC，以识别已绑定但未启动的 IIS FTP 站点。
- 默认用户名是 `camera`，允许修改；全局共用一套 FTP 账户。首次配置时选择活动、填写用户名和密码、确认控制端口，再由“配置并启动 FTP”一次完成 UAC、冲突检测、账户、IIS、ACL、防火墙和启动，不要求先单独保存账户或先做管理员诊断。
- 普通 FTP 不加密用户名、密码和图片内容，只能在可信 Wi-Fi / 有线局域网或 Windows 热点中使用；必须设置专用且不复用的 FTP 密码。
- 同一时间只有一个“当前 FTP 接收活动”，与界面正在查看的活动无关。当前 FTP 活动不能归档、逻辑删除或永久删除。
- IIS 物理路径、相机原图最终目录和 watcher 目录统一为 `working/{event_slug}/原图/相机FTP/`。工作台只使用这一目录，不创建或迁移其他相机 FTP 接收目录。
- watcher 会在 JPG / JPEG 文件大小和修改时间稳定后原地登记该原图，不复制、不移动、不重命名，再完成 hash 去重、EXIF、缩略图、预览图、SQLite、任务中心和 Socket.IO 广播。
- “停止 FTP”只停止工作台管理的 IIS FTP 站点，保留当前活动、目录和 watcher；解除活动关联是独立次要操作，只能在 FTP 已停止且没有上传/导入中文件时执行。
- 多台相机可以共用同一账户同时上传，但应为不同相机设置不同文件名前缀，避免同名文件被覆盖。

活动切换使用独立原子事务：先记录 Site ID、physicalPath、站点运行状态、watcher 和 `activeEventId`，再由单次 IIS `set-path` 子事务更新目标 ACL、路径并恢复原站点运行状态。只有 IIS、binding、监听（原站点运行时）、watcher 和目标活动全部验证通过，才提交新的 `activeEventId`。切换失败会分别报告真实阶段，并逐项验证旧路径、旧 watcher、旧站点状态和旧活动关联是否恢复；前端下拉选择在成功前只表示“待切换”，不会冒充当前接收活动，操作期间也不会被普通状态轮询覆盖。

相机参数：

| 参数 | 填写值 |
| --- | --- |
| 服务器类型 | FTP |
| 地址 | 工作台实时显示的 WLAN IPv4 或 Windows 热点 IPv4 |
| 端口 | 工作台页面显示的当前控制端口（默认 `21`） |
| 文件夹 | `/` |
| PASV | 开启 |
| 匿名登录 | 关闭 |
| 代理服务器 | 关闭 |

同一 Wi-Fi 模式下，相机与主机使用同一 WLAN；校园网有客户端隔离时，使用 Windows 移动热点，其常见主机地址为 `192.168.137.1`。两类地址会同时展示，以当前实际检测为准。已通过 Nikon Z6III 真机验证；其他支持标准 FTP 上传的相机也可按相同参数尝试连接，但尚未逐型号验证兼容性。

IIS 普通状态和文件 watcher 不能可靠提供持续在线会话数。页面因此只在检测到接收、稳定或导入活动时显示“正在传输”，在最近 5 分钟存在文件活动时显示“最近有相机连接”，并明确说明这不代表相机仍在线；没有可靠数据时显示“连接状态未知”，不会伪造实时连接数或客户端 IP。IIS 站点日志目录在普通权限下可能不可读，深度诊断仍需管理员权限。

自动回归（不修改 IIS 站点）：

```powershell
pnpm test:camera-ftp
```

“配置并启动 FTP”、“自动配置并启动 FTP”和“接管现有站点”都是需要确认的管理操作；仅校正已有托管配置时使用“一键修复”。普通权限只能部分读取 IIS 时，状态接口仍成功返回，实际系统修改由用户确认后自动请求 UAC。端口冲突会区分工作台托管站点、可显式接管站点、无关 IIS 站点、其他进程与 Windows 保留端口；工作台不会静默接管、停止进程、修改无关站点或自动改用候选端口。

alpha.4 修复了 Windows PowerShell 5.1 对无 BOM UTF-8 提权启动脚本的解析问题。每次管理员操作现在使用独立操作目录、结构化阶段状态和结果 JSON；失败页面显示失败阶段、建议、脱敏技术详情和重试入口。管理员只读诊断会保留提权后的完整结果，不再回退成普通权限 unknown；站点预检只读取身份、路径和 binding，单个站点的 FTP 子配置异常不会阻断冲突发现。

自定义控制端口通过冲突检测后，工作台会在同一次 UAC 操作中按站点作用域写入 IIS FTP Authorization Rules。alpha.4 已修复把该授权配置误当作站点内嵌 `ftpServer/security` 子元素而导致 22 等端口配置失败的问题；失败回滚和账户更新也复用同一授权配置路径。

防火墙修复只会自动创建或校正工作台稳定内部名称的规则。检测到早期版本以 GUID 为内部名称创建的本地 FTP 规则且内容需要改变时，首次 UAC 只做预检，随后弹出第二个高风险确认框，列出控制/被动端口和远程作用域的当前值与目标值；用户确认后才更新。组策略、动态或来源不明的规则不会被强制修改。规则更新使用 `-NewDisplayName`，失败时恢复原端口、作用域和启用状态，并在技术详情中保留脱敏的实际失败命令与系统错误。

IIS FTP 站点启停使用站点级 `ftpServer.Start/Stop` 和 `ftpServer.state`，与共享的 Windows `FTPSVC` 服务分开检测。配置失败时页面会分别指出“启动 FTPSVC”“启动目标 FTP 站点”或“验证实际端口监听”，并在技术详情中提供 HRESULT、服务/站点状态和回滚提示；不会把目标站点失败误报成 Windows 服务不可用。

alpha.4 还兼容 IIS / Windows PowerShell 5.1 把 FTP 运行状态返回为数值枚举的情况：`1` 按 `Started`、`3` 按 `Stopped` 处理。此前日志中的 “runtime state remained '1'” 属于解析假失败，并非站点真的无法启动。站点启动异常现在额外收集目标 Site ID、binding、physicalPath、FTPSVC、端口归属、只读 appcmd 结果和近期 IIS / FTP / WAS 系统事件；防火墙明确不作为 IIS 站点启动阻塞原因。

最终配置验证同样兼容 Microsoft.Web.Administration 返回的 IIS schema 数值：SSL `0` 归一化为 `SslAllow`、授权类型 `0` 归一化为 `Allow`、权限 flags `3` 归一化为 `Read, Write`，同时在技术详情保留 raw 值。验证失败会返回具体检查码和 expected/actual，不再统一成笼统失败；防火墙回滚使用 NetSecurity 枚举值，并在恢复后逐字段复核原快照。

管理员脚本验证通过后，工作台还会复核已保存的 `activeEventId`、`managedSiteId`、控制/被动端口以及 watcher 的运行状态、活动和目录。任一项不一致都会返回独立错误码，并恢复本轮 Node 配置与 watcher 快照，不会把半提交的本地状态显示为成功。

页面每 5 秒刷新网络地址；临时从 Wi-Fi 切换到 Windows 热点（或反向切换）时会自动选择新的推荐地址。IIS 始终绑定所有未分配地址和当前控制端口，因此不需要随网卡地址重绑。仓库或活动路径变化会标记为可自动修复，并在用户确认 UAC 后同步 IIS physicalPath 与 watcher，不移动已有文件。

图片仓库可以位于 OneDrive Files On-Demand 目录。工作台会区分 OneDrive 云占位目录与真正的符号链接/目录联接；前者允许作为相机 FTP 根目录，后者为避免越出活动目录仍会拒绝。

IIS 的 PASV 端口范围是服务器级配置，默认 `50000-50100`，可在高级设置中修改。初始化、修复或接管会明确提示该设置可能影响本机其他 IIS FTP 站点；取消 UAC 不执行修改。

## 数据安全说明

- 图片仓库路径由用户选择，软件不会主动删除用户仓库根目录。
- 图片原图、缩略图、预览图、已修图、导出包和归档内容保存在图片仓库中。
- SQLite 数据库只保存元数据、文件路径、状态和操作日志，不存储图片二进制。
- 手动备份会生成到当前图片仓库的 `metadata/database-backups/`。
- 启动自动备份默认启用，并按节流策略生成自动备份。
- 数据库位置迁移会先备份，再复制数据库到新位置。
- 迁移失败不会修改配置。
- 旧数据库不会自动删除。
- 数据库备份、迁移和归档不会删除用户原图仓库。

## 常见问题

### 客户端无法连接怎么办

1. 确认主机端软件已启动，并已选择“启动为主机”。
2. 使用主机首页显示的真实地址和端口，不要使用旧截图、旧二维码或客户端本机的 `localhost`。
3. 确认客户端与主机在同一 Wi-Fi、有线局域网或 Windows 热点下。
4. 校园网可能存在设备隔离，同一 Wi-Fi 下也可能无法互访。
5. 校园网不通时，建议主机开启 Windows 热点，客户端连接热点后访问主机。
6. Windows 热点常见主机地址候选为 `192.168.137.1`，不是唯一固定值，请以主机首页显示结果为准。
7. 检查 Windows 防火墙是否允许本软件访问专用网络。
8. 仍无法连接时，在系统设置中复制诊断信息，并连同客户端错误提示一起发送给维护人员。

### 图片无法预览怎么办

1. 确认图片原图仍在仓库中，没有被手动移动或删除。
2. 确认导入任务或客户端上传处理任务已经完成。
3. 尝试刷新图片墙。
4. 查看任务中心是否有缩略图或预览图生成错误。
5. 如果是归档活动，只读历史依赖归档缩略图，需确认归档目录仍存在。

### 导入失败怎么办

1. 确认图片格式为 JPG / JPEG / PNG。
2. 确认仓库路径存在且可读写。
3. 确认源文件未被其他程序占用。
4. 查看任务中心错误列表。
5. 同一活动内重复图片会计入 skipped，不属于失败。

### 任务失败怎么办

1. 打开任务中心查看失败任务。
2. 展开错误列表查看文件名和原因。
3. 修复路径、权限或文件占用问题后重新执行。
4. 对导入、上传、回传等处理类任务，取消或失败不会删除已成功处理的图片。

### 如何查看日志

进入“系统设置 / 故障排查”，点击“打开日志目录”。

### 如何复制诊断信息

进入“系统设置 / 故障排查”，点击“复制诊断信息”。诊断信息包含版本、运行模式、端口、数据库路径、仓库路径、局域网地址和当前活动摘要。

### 为什么校园网无法连接

校园网经常启用设备隔离、跨网段限制或防火墙策略。即使主机和客户端连接同一个 Wi-Fi，也可能无法互相访问。现场使用时建议优先准备 Windows 热点方案。

### 为什么推荐 Windows 热点

Windows 热点能让主机和客户端处在更可控的小型局域网内，减少校园网隔离、防火墙和跨网段问题。热点场景下主机常见地址候选为 `192.168.137.1`，但请以页面检测结果为准。

## 已知限制

- 当前推荐 ZIP 便携包。
- 暂不提供 NSIS 安装包。
- 暂不支持单文件 portable exe。
- 暂不支持 RAW / HEIC / 视频。
- 暂不支持远程传输和云同步。
- 相机 FTP 传输当前使用局域网 Windows IIS FTP，不支持公网 FTP、FTPS / SFTP 或断点续传。
- 当前便携 ZIP 中的提权 PowerShell 脚本随应用分发，但尚无代码签名或受保护安装目录。稳定发布前应改用签名且受保护的安装/提权辅助程序；现阶段只运行来源可信、未被修改的构建产物。
- 暂不提供账号、登录和权限系统。
- 客户端拖拽文件夹上传暂不支持。
- 主机拖拽文件夹导入当前仅扫描第一层。
- 手机和平板浏览器只作为轻量访问入口，不覆盖完整批量上传、批量下载、导出、归档和永久删除流程。

## 开发与构建

开发环境建议：

- Windows 11
- Node.js v22.22.2 LTS
- pnpm
- VS Code

常用命令：

```bash
pnpm install --registry=https://registry.npmmirror.com
pnpm dev
pnpm build
pnpm dist:portable
```

`pnpm dist:portable` 会生成 Windows ZIP 便携包到 `release-pack/`。本轮 `v1.1.0-alpha.4` 不打包、不打 tag、不创建 Release。

Electron Builder 会通过 `extraResources` 把 `scripts/windows/*.ps1` 放入打包资源目录，供 IIS 状态与显式管理操作使用。普通应用启动仍使用非管理员权限，不应修改 NSIS 为默认提权。
