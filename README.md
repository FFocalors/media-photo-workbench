# Media Photo Workbench / 融媒体图片工作台

## 项目简介

Media Photo Workbench / 融媒体图片工作台 是面向校园融媒体中心、新闻中心和影像部门的 Windows 桌面端图片工作台。

它用于活动现场图片导入、筛选、修图流转、客户端协作、导出发布和归档管理。系统以一台主机为中心，集中保存图片仓库和 SQLite 数据库，多台客户端设备可在同一局域网内上传图片、查看图片墙、打星、分类、修改状态、下载待修包并回传已修图。

本项目不是云盘，也不是实时传图系统。当前重点是本地主机集中存储和局域网协作。

## 当前版本

- 当前版本：`v2.1.1`
- 版本主题：相机 FTP 转为手工配置，退役 IIS 自动安装与配置
- `v1.1.0` 仅作为内部开发节点，不创建正式发布；项目从 `v1.1.0-alpha.4` 直接进入本版本线

- 后续稳定版仍以 Windows ZIP 便携包作为主要交付方式

## 使用方式

1. 下载发布页提供的 Windows ZIP 便携包。
2. 将 ZIP 解压到非系统盘目录，例如 `D:\MediaPhotoWorkbench`。
3. 双击根目录的 `Media Photo Workbench.exe`。其余运行文件统一位于 `runtime/`，请勿移动或删除该文件夹。
4. 不要直接在压缩包内运行程序。
5. 首次使用建议先进入系统设置，选择图片仓库路径。

## 主机端快速开始

1. 启动软件，选择“启动为主机”。
2. 进入“系统设置”，设置图片仓库路径。
3. 进入“活动管理”，创建并激活活动。
4. 进入“导入图片”，导入 JPG / JPEG / PNG 图片。
5. 在主机首页查看本机地址、局域网地址和二维码。
6. 等待客户端通过地址或二维码连接。

主机端负责活动、仓库、数据库、图片处理、任务中心、导出发布和归档。

## 客户端快速开始

1. 确认客户端设备与主机在同一局域网，或连接到主机开启的 Windows 热点。
2. 通过主机首页显示的地址或二维码打开客户端页面。
3. 设置设备名，例如“修图电脑A”或“摄影组1号”。
4. 选择活动并上传 JPG / JPEG / PNG 图片。
5. 在客户端图片墙进行查看、打星、分类和状态修改。
6. 在客户端修图任务页下载待修包并回传已修图。

客户端设备名会保存在本机浏览器 / 客户端 localStorage 中，用于主机识别上传来源和操作记录。

## 推荐网络方式

- 同一 Wi-Fi 或有线局域网可用时，直接使用主机首页显示的局域网地址。
- 校园网可能存在设备隔离，即使连接同一个 Wi-Fi 也可能无法互访。
- 如果校园网无法连接，推荐主机开启 Windows 热点，其他设备连接该热点。
- Windows 热点常见主机地址候选为 `192.168.137.1`，实际地址和端口以主机首页 / 相机 FTP 页面检测结果为准。
- 必要时检查 Windows 防火墙是否允许本软件访问专用网络。

## 相机 FTP 传输（v2.1.1）

`v2.1.1` 起，相机 FTP 不再由工作台自动配置 Windows。工作台不再启用 Windows 功能、创建或修改本地账户、写 ACL、写防火墙规则，也不会接管用户已有的 IIS 站点；`setup`、`repair`、`adopt-site`、`discover-sites`、`credentials`、`provisioning-plan` 和 `pending-provisioning` 接口已退役，统一返回 `410 IIS_AUTOMATION_REMOVED` 并指向应用内指导的对应分节。

配置由用户在 IIS 中按应用内指导手工完成一次，工作台此后只负责只读检测、站点启停、切换接收活动和图片导入。

### 配置指导

应用内指导位于“导入图片 > 相机 FTP → 配置指导”，路由 `/host/help/camera-ftp`，随应用离线提供，共 12 节：配置前准备、启用 IIS FTP 组件、检查 Microsoft FTP Service、创建相机 FTP 账户、创建工作台 FTP 站点、绑定控制端口、身份验证与授权、配置可继承的目录权限、被动端口、Windows 防火墙、验证配置、常见问题。文中的 PowerShell 示例默认折叠，并区分只读与管理员操作。

推荐配置：

- 站点名称 `MediaPhotoWorkbenchFTP`，binding 为 `*:{当前控制端口}:`；控制端口默认 `21`，可在 `1-65535` 内修改，但不得落入被动端口范围。
- 普通 FTP、不启用 SSL、basic 身份验证开启、匿名身份验证关闭。
- 服务器级 PASV 端口范围默认 `50000-50100`。该范围属于 IIS 服务器级设置，会影响本机其他 IIS FTP 站点，修改前需自行确认影响。
- 默认用户名 `camera`，密码由用户自行设置，且不得与 Windows 登录密码复用。账户描述必须是 `Media Photo Workbench Managed FTP Account`，工作台以此判断账户归属；描述不符时按“非工作台账户”处理，不参与管控。
- 接收目录需要为该账户授予可继承的 Modify 权限。工作台只校验目标目录是否已继承该权限，不会代为修改 ACL；缺失时返回 `FTP_DIRECTORY_PERMISSION_REQUIRED` 并指向指导的“目录权限”一节，由用户在资源管理器中手工授予。
- 相机 FTP 需要 Windows 11。普通 FTP 不加密用户名、密码和图片内容，只能在可信 Wi-Fi、有线局域网或 Windows 热点中使用，并应使用专用且不复用的 FTP 密码。

密码不进入工作台：不写入 `config.json`、SQLite、API 响应、日志或诊断信息，页面也不回显或复制密码；旧版本遗留的明文密码字段会在启动时清理。

### 工作台仍会执行的操作

- 只读状态检测：读取 Windows 功能、FTPSVC 服务、站点、binding、身份验证、授权、账户、目录权限、被动端口和防火墙规则的当前状态。非管理员检测会跳过可能长时间阻塞的 IIS ServerManager 读取并返回 `ADMIN_REQUIRED` 提示；关键项为 `unknown` 时页面显示“需管理员确认”，由用户按需触发一次管理员只读检测（UAC），不会把未知状态当成“已配置”或“已停止”。
- 端口监听判断不会把 `Get-NetTCPConnection` 的 Access Denied 当成“端口未监听”：脚本会回退到无需管理员权限的 `netstat` 读取目标端口，两种方式都不可用时保持 `unknown`。后台轮询为 15 秒、禁止并发，并复用 30 秒内的可信快照；单次检测超时保留最近一次已确认状态并继续重试。
- 启动 / 停止 / 运行时重启：只操作工作台托管的 IIS FTP 站点，按已保存的 Site ID 精确定位，不停止共享的 FTPSVC，也不停止或修改无关 FTP 站点。当普通权限只能确认服务与端口正常、无法读取站点运行状态时，页面仍允许发起“停止 FTP”，由 UAC 完成精确停止。
- 切换接收活动：先记录 Site ID、physicalPath、站点运行状态、watcher 和 `activeEventId`，再由单次 `set-path` 子事务更新 IIS 物理路径并恢复原站点运行状态。只有 IIS、binding、监听、watcher 和目标活动全部验证通过才提交新的 `activeEventId`；失败时报告真实阶段，并逐项验证旧路径、旧站点状态和旧活动关联是否恢复，同时明确标注是否已发生修改、是否需要回滚。
- 控制端口冲突检测与打开接收目录。
- 保存的接收活动失效（被删除或不再允许接收）时，运行中的站点仍可停止，也可执行一次仅针对现有站点的运行时重启；该重启不采用页面下拉框中的活动、不修改旧 physicalPath、不恢复 watcher。站点停止后必须明确切换到新的有效接收活动才能再次启动接收，避免旧目录被静默重新启用。
- 从失效活动切换到有效活动时，不要求旧活动记录仍存在：工作台通过托管 Site ID 读取 IIS 中真实的 physicalPath 与运行状态，保存为回滚快照后再切换目录与 watcher，目标活动只在完整验证通过后提交。

手工配置缺项会阻断站点启停与活动切换，并在页面给出错误码和对应的指导分节；被动端口范围与防火墙规则不符不阻断启停，但会提示相机传输可能失败。

### 目录、活动与导入

- 同一时间只有一个“当前 FTP 接收活动”，与界面正在查看的活动无关。当前 FTP 活动不能归档、逻辑删除或永久删除。
- IIS physicalPath、相机原图最终目录和 watcher 目录统一为 `working/{event_slug}/原图/相机FTP/`。工作台只使用这一目录，不创建或迁移其他接收目录；旧版本的 `ftp/` 与 `camera_ftp_upload` 目录不删除、不自动迁移。
- watcher 在 JPG / JPEG 文件大小和修改时间稳定后原地登记该原图，不复制、不移动、不重命名，再完成 hash 去重、EXIF、缩略图、预览图、SQLite、任务中心和 Socket.IO 广播。处理成功的文件指纹会持久化，工作台重启时不重复导入未变化的历史文件；停机期间新增或内容发生变化的文件仍会正常处理。
- 多台相机可以共用同一账户同时上传，但应为不同相机设置不同文件名前缀，避免同名文件被覆盖。
- “停止 FTP”只停止工作台管理的站点，保留当前活动、目录和 watcher；解除活动关联是独立次要操作，只能在站点已停止且没有上传 / 导入中文件时执行。
- 相机 FTP 页在站点运行时优先显示当前活动、连接参数、近期相机活动和最近接收文件。最近文件按同一落盘路径只展示最新有效状态，用绿色表示导入成功、蓝色表示接收或处理中、黄色 / 灰色表示跳过，只有真实失败使用红色；账户、端口、IIS 深度检测与高级管理按需展开。

### 当前限制

- 当前仅支持 Windows 11 和局域网普通 FTP；不支持 FTPS、SFTP、公网远传、RAW 或视频。
- 控制端口默认并推荐使用 `21`，可在 `1-65535` 范围内修改；工作台按该值校验站点 binding，并要求 binding 覆盖所有未分配地址，不把热点 IP 写死到 IIS。控制端口不能落入被动端口范围。
- 端口冲突检测会区分工作台托管站点、无关 IIS 站点、其他进程和 Windows 保留端口；工作台不会静默接管、停止进程、修改无关站点，也不会自动改用候选端口。

### 相机参数

| 参数 | 填写值 |
| --- | --- |
| 服务器类型 | FTP |
| 地址 | 工作台实时显示的 WLAN IPv4 或 Windows 热点 IPv4 |
| 端口 | 工作台页面显示的当前控制端口（默认 `21`） |
| 文件夹 | `/` |
| PASV | 开启 |
| 匿名登录 | 关闭 |
| 代理服务器 | 关闭 |

同一 Wi-Fi 模式下，相机与主机使用同一 WLAN；校园网有客户端隔离时，使用 Windows 移动热点，其常见主机地址为 `192.168.137.1`。两类地址会同时展示，以当前实际检测为准。已通过 Nikon Z6III 真机验证；其他支持标准 FTP 上传的相机也可按相同参数尝试连接，但尚未逐型号验证兼容性。

### 状态与诊断

- 普通权限只能部分读取 IIS 时状态接口仍正常返回；站点启停、运行时重启和切换接收活动这些真实系统修改都由用户确认后请求 UAC，工作台不会静默接管站点、停止进程、修改无关站点或自动改用候选端口。
- 管理员只读诊断的结果会被保留，不会被后续普通权限轮询覆盖成 `unknown`。
- IIS FTP 站点启停使用站点级 `ftpServer.Start/Stop` 和 `ftpServer.state`，与共享的 Windows `FTPSVC` 服务分开检测；不会把目标站点失败误报成 Windows 服务不可用。
- 站点启动异常会收集目标 Site ID、binding、physicalPath、FTPSVC 状态、端口归属、只读 appcmd 结果和近期 IIS / FTP / WAS 系统事件，并在技术详情中给出具体检查码与 expected / actual。
- 管理员脚本验证通过后，工作台还会复核已保存的 `activeEventId`、`managedSiteId`、控制 / 被动端口以及 watcher 的活动与目录，任一项不一致都会返回独立错误码，不会把半提交的本地状态显示为成功。
- 页面每 5 秒刷新网络地址；从 Wi-Fi 切换到 Windows 热点（或反向切换）时自动改用新的推荐地址。IIS 绑定覆盖所有未分配地址，因此不需要随网卡地址重绑。
- 图片仓库可以位于 OneDrive Files On-Demand 目录：工作台会区分 OneDrive 云占位目录与真正的符号链接 / 目录联接，前者允许作为相机 FTP 根目录，后者为避免越出活动目录仍会拒绝。
- IIS 的 PASV 端口范围是服务器级配置，默认 `50000-50100`；工作台会校验该范围，但不再代为修改。

IIS 普通状态和文件 watcher 不能可靠提供持续在线会话数。页面因此只在检测到接收、稳定或导入活动时显示“正在传输”，在最近 5 分钟存在文件活动时显示“最近有相机连接”，并明确说明这不代表相机仍在线；没有可靠数据时显示“连接状态未知”，不会伪造实时连接数或客户端 IP。IIS 站点日志目录在普通权限下可能不可读，深度诊断仍需管理员权限。

自动回归（不修改 IIS 站点）：

```powershell
pnpm test:camera-ftp
```

## 数据安全说明

- 图片仓库路径由用户选择，软件不会主动删除用户仓库根目录。
- 图片原图、缩略图、预览图、已修图、导出包和归档内容保存在图片仓库中。
- SQLite 数据库只保存元数据、文件路径、状态和操作日志，不存储图片二进制。
- 手动备份会生成到当前图片仓库的 `metadata/database-backups/`。
- 启动自动备份默认启用，并按节流策略生成自动备份。
- 数据库位置迁移会先备份，再复制数据库到新位置。
- 迁移失败不会修改配置。
- 旧数据库不会自动删除。
- 数据库备份、迁移和归档不会删除用户原图仓库。

配置和数据库启动采用显式版本账本与 fail-closed 策略：损坏或未来版本的 `config.json` 不会被空配置覆盖，已知字段类型损坏和保存失败会保留旧文件；SQLite 迁移会核对账本与实际 schema，高风险表重建前生成并校验受控备份，迁移失败不发布数据库连接。活动永久删除在首次目录移动前先落盘不可变恢复日志，再隔离受控目录；数据库失败恢复原路径，提交后清理失败明确显示部分成功，进程异常退出后由启动恢复按 SQLite 中活动是否存在决定恢复目录或继续清理。`server.log` 在打开前按大小轮转且不触碰当前写入文件。设置页“一键复制诊断”只收集白名单状态，并用父子 `operationId` 关联 API、orchestrator、PowerShell、回滚和前端错误，不包含 FTP 密码、图片路径 / 内容、提权输入或其他 IIS 站点配置。

## 常见问题

### 客户端无法连接怎么办

1. 确认主机端软件已启动，并已选择“启动为主机”。
2. 使用主机首页显示的真实地址和端口，不要使用旧截图、旧二维码或客户端本机的 `localhost`。
3. 确认客户端与主机在同一 Wi-Fi、有线局域网或 Windows 热点下。
4. 校园网可能存在设备隔离，同一 Wi-Fi 下也可能无法互访。
5. 校园网不通时，建议主机开启 Windows 热点，客户端连接热点后访问主机。
6. Windows 热点常见主机地址候选为 `192.168.137.1`，不是唯一固定值，请以主机首页显示结果为准。
7. 检查 Windows 防火墙是否允许本软件访问专用网络。
8. 仍无法连接时，在系统设置中复制诊断信息，并连同客户端错误提示一起发送给维护人员。

### 图片无法预览怎么办

1. 确认图片原图仍在仓库中，没有被手动移动或删除。
2. 确认导入任务或客户端上传处理任务已经完成。
3. 尝试刷新图片墙。
4. 查看任务中心是否有缩略图或预览图生成错误。
5. 如果是归档活动，只读历史依赖归档缩略图，需确认归档目录仍存在。

### 导入失败怎么办

1. 确认图片格式为 JPG / JPEG / PNG。
2. 确认仓库路径存在且可读写。
3. 确认源文件未被其他程序占用。
4. 查看任务中心错误列表。
5. 同一活动内重复图片会计入 skipped，不属于失败。

### 任务失败怎么办

1. 打开任务中心查看失败任务。
2. 展开错误列表查看文件名和原因。
3. 修复路径、权限或文件占用问题后重新执行。
4. 对导入、上传、回传等处理类任务，取消或失败不会删除已成功处理的图片。

### 如何查看日志

进入“系统设置 / 故障排查”，点击“打开日志目录”。

### 如何复制诊断信息

进入“系统设置 / 故障排查”，点击“复制诊断信息”。诊断信息包含版本、运行模式、端口、数据库路径、仓库路径、局域网地址和当前活动摘要。

### 为什么校园网无法连接

校园网经常启用设备隔离、跨网段限制或防火墙策略。即使主机和客户端连接同一个 Wi-Fi，也可能无法互相访问。现场使用时建议优先准备 Windows 热点方案。

### 为什么推荐 Windows 热点

Windows 热点能让主机和客户端处在更可控的小型局域网内，减少校园网隔离、防火墙和跨网段问题。热点场景下主机常见地址候选为 `192.168.137.1`，但请以页面检测结果为准。

## 已知限制

- 当前推荐 ZIP 便携包。
- 暂不提供 NSIS 安装包。
- 暂不支持单文件 portable exe。
- 暂不支持 RAW / HEIC / 视频。
- 暂不支持远程传输和云同步。
- 相机 FTP 传输当前使用局域网 Windows IIS FTP，需要 Windows 11 并在 IIS 中手工完成一次配置；不支持公网 FTP、FTPS / SFTP 或断点续传。
- 当前便携 ZIP 中的提权 PowerShell 脚本随应用分发，但尚无代码签名或受保护安装目录。稳定发布前应改用签名且受保护的安装/提权辅助程序；现阶段只运行来源可信、未被修改的构建产物。
- 暂不提供账号、登录和权限系统。
- 客户端拖拽文件夹上传暂不支持。
- 主机拖拽文件夹导入当前仅扫描第一层。
- 手机和平板浏览器只作为轻量访问入口，不覆盖完整批量上传、批量下载、导出、归档和永久删除流程。

## 开发与构建

开发环境建议：

- Windows 11
- Node.js v22.22.2 LTS
- pnpm
- VS Code

常用命令：

```bash
pnpm install --registry=https://registry.npmmirror.com
pnpm dev
pnpm build
pnpm dist:portable
```

`pnpm dist:portable` 会生成 Windows ZIP 便携包到 `release-pack/`。ZIP 根目录只保留 `Media Photo Workbench.exe` 启动入口和 `runtime/` 运行环境目录；用户双击根目录入口即可启动。`v2.1.1` 的 ZIP 应从对应 Tag 构建；GitHub Release 已提供 `MediaPhotoWorkbench-v2.1.1-x64.zip`。

Electron Builder 会通过 `extraResources` 把 `scripts/windows/*.ps1` 放入打包资源目录，供 IIS 状态与显式管理操作使用。普通应用启动仍使用非管理员权限，不应修改 NSIS 为默认提权。
