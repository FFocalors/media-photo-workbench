OPEN SOURCE · PRODUCT ARCHITECTURE

把图片工作流，
放回团队自己的现场。

frameflow 是一套以 Windows 主机为中心的局域网图片协作工作台。图片与数据库留在主机，成员通过桌面端或浏览器协同完成导入、筛选、修图流转、导出与归档。

产品版本 v2.1.1Electron · React · Node.js · SQLiteMIT License

01 / SYSTEM MAP

一台主机，
多种协作入口

主机是唯一的数据与服务中心。桌面工作台管理本地工作流，局域网浏览器访问同一套前端和 API；手机、平板适合轻量查看与筛选，不承担批量生产任务。

02 / TECHNOLOGY

技术选型围绕
本地可控与易交付

桌面壳与 Web 界面共享前端，后端服务运行在主机本地。数据库、媒体文件、配置和日志分开管理，避免把大型媒体资产塞进应用数据层。

桌面与界面

  • Electron：Windows 桌面应用与主机启动入口
  • React、Vite、TypeScript、Tailwind CSS：共享 UI 与网页构建
  • Zustand、React Router：界面状态与页面导航

本地服务与媒体处理

  • Node.js、Express：主机 API 与静态前端托管
  • Socket.IO：状态变更和协作事件广播
  • SQLite、better-sqlite3：元数据与业务记录
  • sharp、exifr、chokidar：图像衍生、EXIF 与目录监听

交付与运行

  • Windows 便携 ZIP 与 NSIS 安装包
  • 开发前端 Vite 5173；后端在 3030–3040 中选择端口
  • 生产模式由 Express 提供前端、API 与 Socket.IO
  • 配置、数据库和日志写入 Electron 用户数据目录

03 / DATA FLOW

从文件进入，
到成果交付

导入来源可以分散，存储与业务记录集中在主机。导入不会移动或覆盖源文件；重复判断在活动范围内进行，导入结果、失败原因和可重试状态进入任务记录。

接收图片

主机本地导入、客户端上传，或相机 FTP 落盘。

登记与去重

记录来源、文件信息与 EXIF；疑似重复时计算 hash。

生成预览

原图保留；生成长边 400px 缩略图与 1600px 预览图。

团队协作

图片墙筛选、打星、分类、状态流转与修图任务分发。

交付与归档

按条件导出发布图；活动结束后生成轻量归档并验证。

04 / STORAGE MODEL

业务元数据与
媒体文件分开保存

SQLite 保存可查询的业务状态与路径引用；图片文件位于用户选定的工作仓库。数据库不应放进图片仓库，也不应由多个设备直接打开同一个 SQLite 文件。

软件运行数据（用户数据目录）

MediaPhotoWorkbench/
├── data/
│   └── app.db              # SQLite / WAL
├── config/
│   └── config.json         # 本机配置
└── logs/                   # 应用日志

图片工作仓库（可自选磁盘）

MediaPhotoWorkspace/
├── working/event_slug/
│   ├── 原图/主机导入/
│   ├── 原图/客户端上传/
│   ├── 原图/相机FTP/
│   ├── 缩略图/  预览图/
│   ├── 待修图/  已修图/
│   └── 导出/  清单/
├── archive/event_slug/
└── temp/
实体主要内容保存原则
events活动标识、名称与状态图片与任务归属活动；相机 FTP 同一时刻只指定一个接收活动。
images原图、衍生图路径、来源、评分与状态数据库保存路径和元数据，不保存图片二进制。
operation_logs / download_logs业务操作与下载记录下载个人取文件与正式导出分别记录。
export_jobs / 任务导出、导入、归档的进度与结果记录成功、失败、跳过数量及错误明细，支持安全重试。

05 / LAN COLLABORATION

集中存储，
多端访问

客户端只通过主机 API 操作业务，上传与下载也由主机协调。实时事件用于更新页面状态，不做多主机数据库同步，也不把 SQLite 暴露给客户端。

连接方式

客户端输入主机局域网地址并测试连接。打包版通过主机端口访问前端、/api 与 Socket.IO；开发模式中，前端使用 Vite 5173，API 使用实际后端端口。

实时通知

Socket.IO 广播图片新增/更新、任务变化、导出创建与归档更新等事件。客户端收到事件后刷新必要数据，不直接修改主机数据库。

设备职责

桌面主机负责导入、批量导出、归档和服务；笔记本浏览器参与上传、筛选、状态调整与下载；移动端定位为轻量查看和筛片入口。

网络边界

校园网可能启用设备隔离、跨网段限制或防火墙策略。连接失败优先检查设备互访、主机地址、服务端口和 Windows 防火墙入站规则。

Windows 热点常见主机地址为 192.168.137.1，但它不是固定地址；应以当前网络接口显示的地址为准。

06 / CAMERA FTP

系统服务由用户掌控，
工作台负责业务接入

相机 FTP 基于 Windows IIS FTP。自 v2.1.1 起，工作台不再自动安装或修改 IIS；IIS 配置由用户按应用内离线指导完成，工作台只在既有配置上做检测与受控操作。

工作台负责

  • 只读检测 IIS FTP 组件、服务、站点、绑定与运行状态。
  • 控制已验证归属的工作台 FTP 站点启停与运行时重启，不停止共享 FTPSVC。
  • 切换接收活动时更新站点 physicalPath、管理文件监听和导入。
  • 切换失败时尝试回滚站点路径、运行状态和 watcher。
  • 稳定后的 JPG/JPEG 在落盘位置登记入库，不复制、移动或重命名原图。

用户负责

  • 在 Windows 中启用 IIS FTP 组件并创建 FTP 站点与账户。
  • 配置身份验证、授权、可继承目录权限、PASV 范围及防火墙。
  • 根据应用内指导检查服务、站点、端口和目录访问权限。
  • 密码由用户在 IIS 设置；工作台不读取、保存或回显密码。
  • 站点不符合预期时，工作台给出问题与指导，不自动接管或修复。
重要边界

IIS 属于操作系统服务，组件、权限与网络环境存在机器差异。为避免未经确认地改变用户系统，安装、账户、ACL、防火墙和站点创建由用户手动完成。

FTP 当前活动唯一；切换前要求目标目录可写，且没有未稳定上传或导入任务。

07 / ENGINEERING NOTES

围绕原图安全
与可恢复性设计

媒体工作流最重要的是原图不被意外破坏、状态有记录、失败能定位。系统将耗时工作建模为任务，并把数据库与文件处理边界显式分开。

原图保护

  • 导入只复制，不移动、不删除、不覆盖来源文件。
  • 相机 FTP 原图原地留存，以路径登记入库。
  • 已修图独立存放并以 edited_path 关联，不覆盖原图。

任务可观察

  • 导入、缩略图、导出和归档都有任务状态。
  • 失败记录包括文件、原因、任务 ID 与重试提示。
  • Socket.IO 广播变化，客户端可及时看到任务更新。

归档与交付

  • 轻量归档保留缩略图、metadata 与清单。
  • 归档先验证完整性，再由用户确认清理工作区。
  • 发布导出和个人下载分开处理，并独立记录。

设计约束为什么
客户端不直接访问 SQLite避免多设备并发写同一数据库文件；所有业务写入经主机 API。
图片不写入数据库原图和衍生图体积大，需要由文件系统承载并允许选择磁盘。
不做真正的分布式同步主机是唯一存储与业务中心，多端通过 API、文件传输和事件通知协作。
系统级配置需用户明确操作Windows IIS、账户、ACL 与防火墙属于主机系统边界，应用不静默修改。
